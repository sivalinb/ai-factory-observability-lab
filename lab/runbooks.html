Telemetry coverage · observability owner

  1. Inspect lab_source_up and last successful collection time.
  2. Check endpoint reachability, authentication, TLS trust and installed-release mappings.
  3. Restore measurements before declaring the associated domain healthy.

GPU health · GPU platform owner

  1. Read the XID code as an event classification, not a counter rate.
  2. Identify the GPU UUID, node, and actual job placement.
  3. Inspect ECC and system diagnostics. Choose a response appropriate to the XID and diagnostics.

Platform, storage and cooling · datacenter / GPU platform owner

  1. Correlate BMC sensor health with GPU temperature, clocks and workload progress.
  2. Inspect PSU redundancy, airflow and fan state.
  3. For a storage fault, inspect NVSM drive/volume health and data input progress.
  4. Record evidence and choose whether the affected node should be drained.

InfiniBand gray failure · fabric owner

  1. Locate the affected port and cable through the topology inventory.
  2. Compare effective BER, symbol error rates, transmit waits and per-rank collective timing.
  3. Use UFM for device-level inspection; consider a cable investigation or fabric support case.
  4. Validate recovery with the same training workload and healthy baseline.

Raw pre-FEC BER alone does not establish workload harm. Collector update frequency constrains detection time.

Ethernet / RoCE · fabric owner

  1. Inspect buffer occupancy, PFC pause durations, ECN and dropped packets.
  2. Check QoS consistency for the actual RoCE deployment.
  3. Correlate the affected path with service queueing and latency.

Rack NVLink · fabric owner

  1. Identify the link, switch domain and partition.
  2. Compare link health with error rates and collective timing.
  3. Use NMX-T and NetQ NVLink diagnostics for the installed rack.

Scheduling · ML platform owner

  1. Compare pending workload waits to actual available and allocated capacity.
  2. Inspect reservations, quotas and idle allocations.
  3. Verify placement across Slurm and Run:ai pools; they do not share GPU ownership in the demo inventory.

Inference · serving owner

  1. Check p95 TTFT, success rate, queue depth and cache occupancy.
  2. Distinguish capacity pressure from fabric or GPU evidence.
  3. Evaluate concurrency and token limits; benchmark before adding capacity.
  4. Inspect NIM Operator cache/service readiness separately from model request performance.

Training progress · training owner

  1. Compare throughput to a healthy baseline for the same workload configuration.
  2. Inspect maximum and per-rank step/collective timing.
  3. Follow the implicated platform or fabric runbook and rerun the workload to validate the hypothesis.
